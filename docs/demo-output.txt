# Quota OS 演示实录

下面两段都是用 tools/capture_demos.py 驱动 qemu-system-aarch64 实际跑出来的串口记录，不是手写的预期输出。
计时来自客户机的通用定时器，不是脚本填的数字。

命令：

    qemu-system-aarch64 -machine virt,gic-version=2 -cpu cortex-a72 -m 128M -nographic -nic none -kernel build/quotaos.bin
    qemu-system-aarch64 -machine virt,gic-version=2 -cpu cortex-a72 -m 64M -nographic -nic none -kernel build/quotaos.bin

================================================================================
场景 A：128MB（普通演示机）
================================================================================

Quota OS microkernel
Version: 010 (4f077b3)
基于三级资源声明的微内核，
保证一级任务永远不卡顿、二级任务运行不卡顿，三级任务则不保证。
[boot] x0=0x44000000 physical RAM span 128 MB (probed)
[boot] DTB at 0x44000000
[boot] DTB memory 134217728 bytes
[boot] system reserve 350 us/period, 16384 KB;
       tier-1 1500 us/period, 13312 KB; guard 80 us/period
[boot] kernel image+bss 481 KB of the 16384 KB system reserve
[boot] GICv2 from DTB: distributor 0x8000000, cpu interface 0x8010000
[boot] CNTFRQ 62500000 Hz (1 tick = 16 ns), virtual timer PPI 27
[boot] tier-1 display-vsync and timer-server bound to their slots
[boot] slot table from tick 625000, period 625000 ticks, guard 1250 ticks
[boot] shell task running

命令（输入数字后回车）:
  1  资源总览：系统预留、Tier 1 槽和浪费、Tier 2、Tier 3
  2  安装应用：允许/拒绝（也可以停止应用）
  3  资源不够：拒绝并说明先关哪个应用
  4  旧设备：超过整机容量的请求被拒绝
  5  Tier 1 准时：抖动和错过都是 0
  6  Tier 1 超时在槽尾被掐断
  7  Tier 1 槽从不外借
  8  Tier 2 最低值有保证，建议值在压力下收回
  9  Tier 3 过载不影响上层
  10 任何一级的失控任务只拖慢自己
  11 设备申请 Tier 1：不能打断的设备被拒（说明缺哪一条）
  12 超额申请被拒（说明是哪种资源）
  13 预算令牌：驱动替谁干活就扣谁的预算
  h  帮助    q  提示如何退出 QEMU
