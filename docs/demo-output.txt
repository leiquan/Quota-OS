# Quota OS 演示实录

下面两段都是在本机用 qemu-system-aarch64 -M virt 实际跑出来的串口记录，不是手写的预期输出。
内核是 prebuilt/quotaos.bin。计时来自客户机的 CNTPCT，不是脚本填的数字。

命令：

    qemu-system-aarch64 -machine virt,gic-version=2 -cpu cortex-a72 -m 128M -nographic -kernel prebuilt/quotaos.bin
    qemu-system-aarch64 -machine virt,gic-version=2 -cpu cortex-a72 -m 64M -nographic -kernel prebuilt/quotaos.bin

128MB 那一次按菜单走完：资源表、分级开/关的优先级对照、失范隔离、用户拒绝启动、超额后关闭再启动、弹性回收、声明超过本机、最小切片、32 个虚拟 CPU。
64MB 那一次只核对「小内存机器」：普通应用能启动，声明 80MB 的 Neural Forge 被拒绝。

=== 最小切片 / minimum useful slice ===
下界来自两件事：定时器实际能稳定响的间隔，和一次任务切换的开销。
切片若比这两者之和还短，声明的 CPU 会被切换吃掉，虚拟 CPU 就没有意义。
CNTFRQ = 62500000 Hz
timer interval probe (guest CNTPCT microseconds):
  requested  samples  min_us  avg_us  max_us
         20        9      34      90     364
         50        9      63      63      65
        100        9     112     113     114
        200        9     213     213     214
        500        9     518     519     522
       1000        9    1017    1019    1024
context-switch probe: two tasks yield to each other, sample = round-trip/2
只统计 1..60 us 的样本，更大的多半是被常驻 tier-1 工作插了一脚。
context switch: n=46 min=3 avg=7 max=28 us
practical lower bound = stable_timer + 2*switch = 50 + 2*7 = 64 us
empirical sweep: 6 tier-2 spinners, each must receive its slice (8 periods)
  slice_us  recv_avg  under_miss  pass
       40        56           0  loose
       80        95           0  PASS
      120       136           0  PASS
      200       218           0  PASS
      300       322           0  PASS
measured minimum useful slice on this QEMU run: 80 us
公式给出的下界是 64 us。演示用的批量切片不会低于测到的最小值。
