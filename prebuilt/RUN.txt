Drop-in kernel for the UTM virtual machine that already boots Quota OS.
Not a WebKit GUI. Replacing this file does not add a window.

What you do
  Keep the VM you already run. Do not change machine type, GIC,
  CPU, memory, serial, or boot arguments.
  Documented setup this image matches: virt, GICv2, Cortex-A72,
  128 MB, no disk, kernel chosen in UTM's file picker, Display
  removed, Serial kept. QEMU Machine Properties stay gic-version=2.
  QEMU Arguments stay -cpu cortex-a72, with no -kernel line.
  Point that same kernel picker at this quotaos.bin and start.

What you should see
  Version: 016 (af050b5)
  [boot] EL1h, MMU off. No hardware isolation.
  [boot] GICv2 from DTB
  select>
  The menu is the serial menu. There is nothing to click.
  A successful boot of an older quotaos.bin does not verify a GUI.
  This image has no HTML, CSS, or JavaScript. engine is not linked.

Banner convention
  af050b5 is git rev-parse --short=7 of the parent of the commit
  that introduced these bytes.

SHA-256
  quotaos.bin afed7949f5b3adc6dcb3d6c86e05356ed69fd315eca55fbeafae656f62880e05
  quotaos.elf bf6338345233296ffac12393f37e477078299ec91c65ce68ab90fa5e656b8f64
  Also in SHA256SUMS.

Same guest on the command line, no extra devices
  qemu-system-aarch64 -machine virt,gic-version=2 -cpu cortex-a72 \
    -m 128M -nographic -nic none -kernel prebuilt/quotaos.bin

Graphics is not in this configuration
  Stock virt (the machine UTM virt + gic-version=2 exposes) has
  fw_cfg and empty virtio-mmio slots. A boot with no added device
  prints: [fb] etc/ramfb not in fw_cfg (9 files)
  and [input] no virtio-input (id 18).
  The documented UTM setup also deletes Display.
  Pixels on screen would require a display device that setup
  removes. This drop-in does not add that device and does not
  ask you to.
