QEMU 8.2.2. The command that produced the screenshot and the input log:

  qemu-system-aarch64 -machine virt,gic-version=2 -cpu cortex-a72 -m 128M \
    -display none -nic none \
    -device ramfb \
    -device virtio-keyboard-device \
    -device virtio-tablet-device \
    -kernel prebuilt/quotaos-lvgl.bin -append lvgl

QEMU prints "Could not open option rom 'vgabios-ramfb.bin'". The guest
still writes etc/ramfb, and screendump returned the screen below.
These are QEMU devices, not UTM menu names.

The screen is a button labeled +1, a count, and a text field. A click at
the button and the keys a then b produced Count: 1 and the text ab.
docs/v016/lvgl/screen.png is that framebuffer. docs/v016/lvgl/trial.raw
is the serial log. Developer self-test, not independent QA.

The same binary with -append e4 (no ramfb required) is
docs/v016/lvgl/e4.raw: item9 PASS, item10 PASS, QA DONE. Tier-1 stays
13312 KB and 1500 us. That run does not draw the UI. A passing display
demo is not a tier-1 guarantee. The address space is EL1 with the MMU
off. It is not separate-process isolation.
